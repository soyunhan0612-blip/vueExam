# Architecture Decision Records

## 철학
면접 시연용 학습 MVP다. 퍼블리싱 역량을 보여 주는 것을 우선한다 (퍼블 60 : Vue 로직 40). 의존성은 최소로 두고, 개념마다 Vue 2와 비교할 수 있는 작고 명확한 구현을 고른다.

---

### ADR-001: Vite 5 + Vue 3.5 `<script setup>`, Vue 2는 주석으로 비교
**결정**: Vue 3 앱 하나만 만들고, Vue 2 대응 코드는 각 파일 상단의 `[Vue 2였다면]` 주석으로 보여 준다.
**이유**: 면접일(2026-09-28)까지 시간이 짧다. 한 파일 안에서 두 버전을 나란히 보는 것이 학습과 설명에 가장 효율적이다.
**트레이드오프**: Vue 2 코드는 실행해서 검증할 수 없다.

### ADR-002: Pinia 스토어를 Options 방식 하나, Setup 방식 하나로 작성
**결정**: `stores/auth.js`는 Options 스토어, `stores/scrap.js`는 Setup 스토어로 만든다.
**이유**: Vuex와 구조가 비슷한 Options 방식과 Composition API 방식을 둘 다 보여 줄 수 있다. Proxy 반응성과 `Vue.set` 함정도 비교할 수 있다.
**트레이드오프**: 스토어 작성 방식이 하나로 통일되지 않는다.

### ADR-003: 백엔드 대신 json-server 목업
**결정**: json-server 0.17(`--delay 400`)과 `mock/db.json`으로 API를 흉내 낸다.
**이유**: 이 과제의 핵심은 프론트엔드다. 지연을 넣으면 로딩 상태와 응답 경쟁 상태 처리도 확인할 수 있다.
**트레이드오프**: 실제 인증과 보안은 없다. 로그인은 `/users?email=` 조회로 흉내만 낸다.

### ADR-004: 필터는 URL 쿼리와 동기화하고 목록은 KeepAlive로 유지
**결정**: 키워드·지역·업직종을 URL 쿼리와 동기화하고, 목록 화면을 `KeepAlive`로 캐시한다. 스크롤은 `scrollBehavior`로 되살린다.
**이유**: 플레이스토어 리뷰에 "상세 들어갔다 나오면 조건 초기화"라는 불만이 있다. 이를 고치는 사이트 개선안으로 시연한다(시나리오 2).
**트레이드오프**: 쿼리와 상태 사이의 동기화 로직이 늘어나고, 캐시된 화면의 데이터가 오래된 것일 수 있다.

### ADR-005: TypeScript와 테스트 코드 제외
**결정**: JavaScript만 쓰고 테스트 코드는 작성하지 않는다. 검증은 `npm run build`와 시연 시나리오로 한다.
**이유**: 기한이 짧고, Vue 2와 비교하는 코드를 단순하게 유지해야 한다.
**트레이드오프**: 타입 안정성과 회귀 테스트가 없다.

### ADR-006: 셀렉트는 네이티브 `<select>` 유지
**결정**: BaseSelect는 네이티브 `<select>`에 스타일만 입힌다.
**이유**: 모바일 OS 기본 선택 UI와 스크린리더 접근성을 그대로 쓸 수 있다.
**트레이드오프**: 옵션 목록 모양을 자유롭게 꾸밀 수 없다.
